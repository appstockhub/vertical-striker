**測れる指標と測れない指標の区分（ユーザー指示による必須の区別）**:
- **距離系（ドリブルギャップ・蹴り出し距離）**: 多フレーム平均で頑健。**測れる** ✅
- **速度系（走速・キック初速・摩擦）**: タイムスタンプで正規化済み。**測れる** ✅（遠近の系統誤差±40%は従来どおり残る）

  十分測れる ✅
- **時間系の細かいもの（キックモーション時間、期待値≦0.1s）**: 実効fps37〜47では**範囲推定のみ**
  （±1〜1.6tick相当のジッター）。⚠️ 下表では範囲で扱う

## 1. 単位の定義

すべて「**選手の身長 = 1**」に正規化した無次元値で比較する（解像度も座標系も異なるため）。

| | 原作（動画） | 自作 |
|---|---|---|
| 身長の実体 | ボール近傍選手スプライトの実測高さ（全身が取れる18〜30ドットのみ採用） | **14.68 world px**（ピッチ幅480px ÷ 32.7人分、19-20周目確定値） |
| 時間 | 提示タイムスタンプ（秒）→ 60fps tick 換算 | 60fps tick |

換算式: `px/tick = (身長/秒) × 14.68 ÷ 60`

### ゲートの読み方・注意

1. **T1/T2は遠近圧縮の系統誤差±40%を含む**。ただし5.7倍/3.3倍という乖離は誤差では説明
   できない（誤差を最大に見積もっても3.4倍/2.0倍速い）。**テンポを落とす方向は確定**
2. **T3（比）とD1（正規化距離）は系統誤差が消える**ため最も信頼できる。サイクル①では
   「T1を許容範囲へ入れ、T3の比4〜6を保つようにT2を連動させる」のが正攻法
3. K1は実効fpsの限界で範囲推定。6tickワインドアップ（承認済み設計）で実装し、
   プレイフィールで微調整する
4. 原作の評判は「とにかく速い」（18周目調査）だが、実測は「選手は遅く、画面窓が狭いから
   速く感じる」ことを示している。**テンポを落としても「速さの体感」は画面設計で保たれる**
   （可視範囲は原作と一致済み＝段階1の成果）
5. 原作のゲーム内時計は実時間の約9倍速（18:05→18:37が実3.6秒）。試合時間設計の参考値

## 3. 再現コマンド

```
# 素性検証(fps/重複):      .analysis/venv/bin/python .analysis/probe_fps.py <video>
# 構図検出:                .analysis/venv/bin/python scripts/video/analyzeOriginal.py geometry <video>
# 追跡(VFR対応):           .analysis/venv/bin/python scripts/video/trackBall.py track <video> --start 0 --dur 371
# 指標算出:                .analysis/venv/bin/python scripts/video/metrics.py scratchpad/frames/track_0_20695.jsonl
```

venv は `.analysis/venv`（gitignore済み。opencv-python-headless + numpy + imageio-ffmpeg）。
テンプレートは frame 5020/5095 から切り出し（`trackBall.py cut`）。追跡の正着はマーカー
画像13枚の目視で確認済み（誤検出0）。

## 4. 自作側の現状値の測り直し方

シナリオテスト（`tests/scenarios/`）が「操作→応答」を機械判定する。テンポ系（T1〜T4）は
定数から直接換算できる（`PLAYER_SPEED_FIXED` 等）が、**変更後は観戦シミュレーターで
実効値を確認すること**（AIの介在で実効速度は定数どおりにならない場合がある）。
