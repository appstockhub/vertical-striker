# V-2: 選手スプライトの素材調達 — 調査と試作の記録

作成: 2026-08-17（23周目）。
背景: 21〜22周目のV-4で背景（芝・スタンド・ゴール）が原作水準に近づいた結果、
ユーザー判断で「残る違和感の主因は選手」となり、選手スプライトの素材調達に着手した。

前提（CLAUDE.md「素材ポリシー」/ 20周目のユーザー決定事項）:

- 原作および他の商用ゲームの素材は一切使用しない（吸い出し・模写・トレース・fan-made含む）
- ライセンス上問題のない第三者素材（CC0 / 商用可の購入素材）は使用可
- **継承（share-alike）義務のあるライセンスは採用しない** — CC-BY-SA / GPL は除外、
  CC-BY（表示のみ）は可
- 使用素材は `docs/asset-credits.md` に必ず記録

### 調査の限界（正直な申告）

- itch.io の一覧/タグページは HTTP 403 で機械的に取得できず、検索＋個別ページ直読みで
  カバーした。**未発見のサッカーパックが存在する可能性は残る。**
- 上記3b（Puny無料版）の方向数と、SmallScaleInt のライセンスは**未解決**。前者はダウンロード、
  後者は問い合わせで確定する必要がある。

### 結論: 要件を完全に満たす素材は「存在しない」

「8方向 × 走行アニメ × 16〜48px × 継承義務なし × ライセンスがページに明記」を**全部**
満たすサッカー専用素材は見つからなかった。20周目の調査結論は今回も変わっていない。
唯一これに近いのが #1（chasersgaming）だが、**ライセンスがページに書かれていない**という
一点だけが未解決で残っている。

### 【重要】頭身の問題は「16x16 で探していること」自体が原因

Puny Characters の調査で判明した構造的な事実:
**16x16 の人型スプライトは物理的に2頭身前後にしかならない。**
16px の中で顔が判別できる頭は 6〜8px を要求し、残り 8〜10px に胴と脚が入るため、
必然的にデフォルメ体型になる。GB素材（約2頭身）も Puny（約1.6頭身）も同じ制約の帰結で、
作者の作風の問題ではない。

したがって**今後の素材探索は「16x16」を要件から外す**こと。
シャツ／短パン／ソックス／スパイクを塗り分け、かつ人間の頭身を保つには、
**キャラクターの全高で 24〜32px 以上**が要る。参考として、当プロジェクトの自作スプライトは
全高42px（キャンバス46px）で 7.25頭身と4色のユニフォームを両立できている（後述の1-C）。
chasersgaming の 16x24 はこの意味でも下限に近い。

## 2. CC0素材（GibbonGL）での試作

`?sprites=gb` を付けた時だけ有効になる比較用スイッチとして実装した
（`src/render/gbPlayerSprites.ts`、既定はOFF＝従来の手続き生成）。
既存の `src/render/playerSprites.ts` は1行も変更していないので、
同じ試合・同じフレームで両方をキャプチャして並べられる。

### 分かったこと: 現行の描画パイプラインには**問題なく乗る**

| 検証項目 | 結果 |
|---|---|
| 8方向への対応 | ✅ 乗る（シート1行 = 1方向、`playerSpriteKey` と同じキー命名で焼き込むだけ） |
| 走行アニメーション | ✅ 乗る（4フレーム。既存の `ANIM_FRAME_COUNT` = 4 と一致） |
| チーム色の差し替え | ⚠️ **技術的には可、しかし意味を成さない**（後述） |
| 接地・遠近スケール | ✅ 無改造で乗る（origin=(0.5,1) と `p.scale` のまま） |
| 60fps | ✅ 起動時に64テクスチャを1回焼くだけ。毎フレームのコストは従来と同じ `setTexture()` のみ |

つまり**パイプラインは外部素材を受け入れられる状態にある**ことが実証できた。
これは今回の最大の収穫で、どの素材を選んでも組み込み作業自体は軽い。

### 実測で確定させたこと（目視だと取り違える箇所）

素材には方向の対応表が付属していないので、行→方向の対応を数値で確定させた:

1. 行0と行4は左右対称、行1..3と行7..5は**全ピクセル一致の鏡像** → 8方向の一巡と確定
2. 明色（目）の画素数が 行0=32 → 行4=6 と単調減少 → 行0=手前（顔）、行4=奥（後頭部）
3. 左右は「明色の重心 − シルエットの重心」で判定。
   行1/2/3 = **−0.25 / −0.53 / −1.70**（顔が左寄り）、行5/6/7 = +1.70 / +0.53 / +0.25

**最初は目視で「行1 = 右向き」と読み違えて実装しており、上記の計測で誤りに気付いて直した。**
CLAUDE.md「検証の絶対原則」の「推測で直さない、先に計測する」がここでも効いた。

### 素材そのものの評価: **このままでは使えない**

比較画像: `.shots/v2-compare-crop.png`（左=現行のベクター生成 / 右=GB素材、同一フレーム
t1200・同一注視点。上段=手前の選手、下段=センターサークル付近）

| 論点 | 現行（ベクター生成） | GB素材 |
|---|---|---|
| **頭身** | 約6頭身の立ち姿 | **頭が全高の約45%のデフォルメ体型**。RPGの村人であってサッカー選手に見えない |
| **ユニフォームの分離** | ジャージ / 短パン / ソックス / スパイクが別色。一目で「サッカーの装い」と読める | **4色固定パレットで肌・服・手足が全部同じ色**。パレット差し替えでは「シャツだけチーム色」にできず、**全身が単色の飴細工**になる |
| **視点の前提** | 俯角16.7°のカメラに合わせて描き起こした立ち姿 | 真上寄りの見下ろし（頭頂と肩を上から見る絵）。**芝は横から、選手は上から**という視点の食い違いが出る |
| **解像度** | 30x46 をそのまま | 16x16 を3倍（48px）。ドットは3px角で粗い |
| **チームの識別** | ○ | ○（琥珀 / 濃紺で成立はする） |

**結論: このCC0素材は「そのまま採用」はできない。**
ただし**素体としては優秀**で、8方向 × 4フレームが揃い、Aseprite生ファイルが同梱され、
ライセンスがページに明記された CC0 で、作者自身が「自分で作り変えてほしい」と書いている。
描き直しの土台としては候補に残す価値がある。

### 試作の後始末について

**GB素材は不採用**（23周目にユーザー判断: 「頭身が2頭身で猿のように見える」）。
ただし**スイッチと素材は残してある**。理由は、外部スプライトシートを
「色キーで背景を抜く → パレットをチーム色へ差し替える → 8方向 × 4フレームで焼き込む →
既存の描画パイプラインに載せる」という経路が**動く形で1本通っている**こと自体が資産で、
別の素材を採用するときそのまま差し替え先になるため。既定は OFF（`?sprites=gb` 指定時のみ）。

## 3. 素材が決まるまでの暫定対応: 自作ベクター生成スプライトの作り直し（1-C）

外部素材の結論が出るまでの間、**手続き生成のスプライト自体を人間らしい体型へ作り直した**
（`src/render/playerSprites.ts`、23周目）。GB素材との比較で「自作の方が人間らしさでは
勝っている」ことが分かったため、そちらを伸ばす方が早いと判断した。

### 実測で分かった出発点

| 項目 | 変更前（実測） | 変更後 | 根拠 |
|---|---|---|---|
| **頭身** | **4.20頭身**（全高42px / 頭の直径10px） | **7.25頭身**（頭の直径 5.79px） | 成人男性アスリートの標準canon（7.5頭身）をわずかに詰めた値 |
| 肩幅 / 頭幅 | 2.00倍 | 2.00倍（維持） | 元から人体の目安どおりだった |
| 歩幅（足の移動量） | 11.0px | **14.5px**（脚長の75%） | 走行として読める最低量を下限0.6・上限1.0で回帰ゲート化 |
| ユニフォーム | シャツのみチーム色。短パンは両チーム共通の濃灰、ソックス白固定 | **シャツ / 短パン / ソックス / スパイクの4色分け**をチームごとに定義（`TeamKit`） | 遠方で上半身が潰れても下半身でチームを判別できる保険 |

**「現行は約6頭身」という当初の見立ては誤りで、実測すると4.20頭身だった。**
目分量の見積もりが1.4倍ずれていたことになる。

### 造形・モーションの変更

- 脚を「腿 → すね（素肌） → ソックス → スパイク」の4区間に分け、**膝を折る**ようにした。
  以前は腿と脚の2本の直線で、走行時に「滑っている」ように見えていた
- 腕を肘で折り、**必ず暗い輪郭線を先に敷く**（素肌色のままだと明るいシャツに埋もれて腕が消えていた）
- 半袖の袖口を追加（無いと腕が肩から直接生えて見える）
- 首を太く短くして頭と胴の分離感を解消、前髪を浅くして顔の面積を残した

### 接触シート（8方向 × 4フレーム）で見つけて直した3件

造形の検証には試合の1コマを拡大するのではなく、**焼き込み済みテクスチャ32枚を一覧に
並べて直接見る**方式を使った（`__vsDebug.getTextureImage` を新設）。これで初めて分かった:

1. **片脚だけが白い棒になるフレームがあった** — ソックスの上端をワールドYで比較していたため、
   脚が浮いたフレームで上下が入れ替わり色が飛んでいた。膝→足首の線分をパラメータで
   分割する方式に変更
2. **手前向きの走行で足がキャンバス下端を突き抜けていた** — 奥行き方向の振り出しが
   接地点より下に出ていた。`Math.min(0, …)` で下方向を封じた
3. **短パンがスカートに見えた** — 短パンの幅がシャツの裾より広かった。0.68倍に細くした

### 回帰ゲート

`tests/render/playerProportions.test.ts`（8件）を新設した。骨格の算出を Phaser 非依存の
純関数 `computePlayerSkeleton()` へ切り出し、頭身 7.0〜7.5 / 関節の順序 / 肩幅比 /
歩幅比 / 短パンとソックスの間に素肌が残ること、を数値で固定している。
**キャンバス寸法（46px）は変更していない** — 画面上の見かけサイズ41.6pxは段階1で
原作と一致を確認した確定値で、`tests/render/viewMetrics.test.ts` の不変条件のため。
