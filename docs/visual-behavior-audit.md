# visual-behavior-audit.md — 定性差分監査の台帳（Visual Behavior Audit）

作成: 2026-08-18（24周目-6）。**発端**: サイクル④の全ゲート合格後もユーザーの実プレイで
7件の問題が発見された。個々のバグ以上の問題は「これらをユーザーが見つけている構造」——
参照動画は最初からあったのに、パイプラインが物理数値しか抽出しておらず、
**見た目・挙動・演出の差分を誰も観察していなかった**。ゲートに入っていないものは
自律ループで直らない。本書はその穴を塞ぐ「定性差分監査」の恒久台帳である。

- 運用ルール: **新機能・修正のたびに該当場面の並置比較を行い、本台帳と突き合わせる**
  （CRITIC.md 原則10）。新しい差分を見つけたら台帳に追記し、重要度「高」は
  修正されるまで停止条件に含める。
- 原作側の証拠: `scratchpad/original-gameplay-01.mp4`（=02と同一内容の重複。1920x1080
  30fps 183.5s、ゲーム画面は (334,185)-(1579,836)、SNES 256x224 の4.87x/2.91x引き伸ばし）。
  フレーム引用は `vf<番号>`（30fps連番）と `t=<秒>` で表記。
- 抽出ツール: `scratchpad/contact_sheet.py`（2fps全景走査）/ `scene_strip.py`（場面30fps）/
  `zoom_strip.py`（矩形拡大）。いずれもゲーム画面へクロップしてから使う（録画に映り込んだ
  個人情報の排除。画像そのものは .gitignore 済みで成果物に持ち込まない）。

## 2. 並置比較の要約（原作にあって自作にない/違うもの）

各場面 5観点（物体・挙動・カメラ・演出・時間）で比較した結果の要約。
自作側の証拠は `.shots/audit-before-midfield.png`（BEFORE、t8458）、
`npm run view:metrics` の実測、コード参照で示す。

### 2-1. 通常プレー（ドリブル/カメラ）
- **カメラ**: 原作はボール位置の可視ピッチ幅 ≈ **選手9人分**（17.7m）、可視奥行き約47m、
  選手の見かけ身長 ≈ 画面高の**27%**（手前）。常時スクロール。
  自作(BEFORE)は可視幅**35.7人分**・奥行き131m・選手 ≈ 画面高6%、ピッチ全幅が
  画面内（横追従不要と表示される）。**約4倍引きすぎ** — `npm run view:metrics` 実測。
- **挙動**: 原作のドリブルは離散タッチ（実装済み・D1/D2合格）。**体感速度は窓の狭さで
  作られる**: 画面上の移動速度 ≈ 2.15身長/s ÷ 可視幅9人分 = 画面幅の約24%/s。
  自作は同じ物理速度でも可視幅35.7人分 → 画面幅の6%/s と**4倍遅く見える**。
- **物体**: 原作は全選手に接地影 + 足元の芝マーク。自作は接地影あり(同等)。
- **演出**: 原作はパスカーソル(赤▽+背番号)が受け手候補に常時表示。自作あり(同等)。
- **同じと判定**: 離散タッチの構造(D1/D2)、背番号バッジ、パスカーソルの存在
  （根拠: vf249-318 と自作ドリルモードの既存ゲート）。

### 2-2. 浮き球の表現
- **物体**: 原作は浮遊中も**濃い楕円影が地面に常時表示**され(vf1876-1904)、ボール本体は
  高度に応じて**劇的に拡大**（地上の約2.5〜3倍、vf690/702）。影は消えない。
  自作: 影は `1/(1+h*0.035)` で縮小し `α=0.35×同係数` で**高いほど消える**
  （`PitchScene.ts renderBall` / `viewConstants.ts BALL_SHADOW_SHRINK_PER_PX`）。
  拡大率も `0.012/px` と微小。→ **「影がない」体験の実体**。
- **挙動**: 原作はCPUがゴールキック・クリア・ロングフィードで浮き球を常用。
  自作は**CPU試合9000tickで ball.height が一度も0を離れない**（実測、__vsDebug.pump）。

### 2-3. スローイン
- **挙動**: 原作はボールがラインを越えると帯表示→ボールは線外に静止→投げ手の
  **頭上にボールが移動し約0.4〜0.5秒保持**(vf2070-2082)→**放物線で投入**(vf2085-2088)。
  自作はキック経路の再開（ボール速度を直接設定、地上球）= **キックイン**。
- **物体**: 原作は頭上保持の専用ポーズ（ボールスプライトが頭上に重なる）。自作に無し。
- **カメラ**: 原作は静止(投げ手がライン際)→投入後に追従再開。
- **演出**: THROW IN 帯が投入直前まで表示され続ける(約2.6秒)。
- **時間**: アウト→再開まで約2.9秒（66.5→69.4）。

### 2-4. ゴールキック（セットプレー演出の型）
- **演出**: 原作は 帯(約2.2秒)→**暗転フェード→ゴール正面へ画面カット**→GK+ガイドバー
  （**丸の連鎖が蹴る方向を示す**、vf633-669）→GKが蹴る→カメラが高速でボールを追う。
  自作はカット無し・ガイドバー無し・その場でロック解除のみ。
- **挙動**: 原作のゴールキックは**高い浮き球**でハーフウェー付近まで飛ぶ(vf672-702)。
  自作はグラウンダー配球。
- **時間**: 停止全体で約3.8秒(18.6→22.4)。

### 2-5. GK（キャッチ/パンチング/ダイブ）
- **挙動(sim)**: 自作simは secured/deflected を既に区別する（`goalkeeperAI.ts
  resolveSaveOutcome`: CATCH_RANGE/CATCH_MAX_SPEED/PUNCH_RANGE=1.5倍）。**差分は描画**。
- **物体**: 原作はGK専用ポーズ群 — 構え→**水平ダイブ**(vf3829)→**倒れ込み維持 約0.5秒**
  (vf3831-3845)→**膝立ちで起き上がり**(vf3849-3851)。パンチは跳んで弾き、こぼれ球が
  前方に生きる(t=144.2-145.6)。キャッチ後は保持して間(1.5s、parity-targets S1)。
  自作のGKはフィールド選手と同じ立ち絵のみ。セーブの瞬間も無反応で、
  **キャッチとパンチが見分けられない**。
- **こぼれ球**: 原作のパンチ後は詰め合いが発生（こぼれ球場面）。自作は deflected の
  y速度符号反転のみで、見た目は「ボールが勝手に反転した」ようにしか見えない。

### 2-6. スライディング/チャージ
- **物体**: 原作のスライディングは**横倒れ専用ポーズ**で地面を滑走(vf3788-3806、約0.6秒)、
  倒れ維持→膝立ち→起立の多段階復帰(vf249-273にも同様の復帰)。
  チャージは**並走して体を寄せ合う**接触表現(vf279-303)で転倒しない。
  自作: スライディングはスプライトの回転(82°)のみ(24周目サイクル③)。チャージは描画ゼロ。
- **挙動**: 「奪えない」報告は修正⑤で計測の上で対処（simの奪取判定 vs 間合い/速度の実測）。

### 2-7. 演出（バナー/セレブレーション/審判）
- 原作のイベント帯: GOAL KICK / THROW IN / FOUL / GOAL / FULL TIME / SENT OFF —
  白抜き大文字、画面中央帯、2〜3秒表示。自作: `render/eventBanner.ts` の実装状況と
  表示対象を修正段階で照合。
- ゴール後は暗転→**大判セレブレーション画面**（国旗+スコア+選手の走り、約5秒）。
  自作は小さな帯のみ。
- 審判スプライトが FOUL/SENT OFF で登場（自作は未実装 — カード/退場自体が未実装スコープ）。

## 4. 測り方の記録（再現手順）

```
# 原作: 全景走査 (2fps コンタクトシート)
python scripts/video/analyzeOriginal.py extract scratchpad/original-gameplay-01.mp4 --fps 2 --start 0 --dur 184 --out scratchpad/frames/cat01
python scratchpad/contact_sheet.py scratchpad/frames/cat01 scratchpad/frames/sheet01 2

# 原作: 場面の30fps精査 / 矩形拡大
python scratchpad/scene_strip.py scratchpad/original-gameplay-01.mp4 <start> <dur> <out.png> --cols 5 --step 2 --tile 500
python scratchpad/zoom_strip.py scratchpad/original-gameplay-01.mp4 <start> <dur> <cx> <cy> <cw> <ch> <out.png>

# 自作: 実測とキャプチャ
npm run view:metrics                      # カメラ框の数値
node scripts/shotSink.mjs 5199            # PNG受け口
# ブラウザ: __vsDebug.pump(n) で駆動し __vsDebug.renderAt(ballY) をPOST
```
