## 1. 原作の測定方法と結果

Web収集した原作プレイ画面 22枚（96 / 95 / 94WCE / 94WCFD / 初代）のうち、SNESネイティブ解像度
(256x224) の6枚を主資料にした。**画像そのものは一切流用していない**（CLAUDE.md「完全オリジナル素材」）。
測定は「既知の実寸（ゴール幅7.32m、ペナルティエリア深さ16.5m、ペナルティアーク弦14.6m、ピッチ幅68m）を
物差しにして、透視投影 `y = y_h + C/z`, `x = W/2 + focal·Δx/z` を当てはめる」方式。

| 項目 | 原作の測定値 |
|---|---|
| 焦点距離 focal | 画面幅の約 1.42 倍 |
| 一度に見えるピッチの奥行き | カメラから約 15m 〜 64m（**約47m**） |
| ボール位置での可視ピッチ幅 | 約 17.7m（≒ 選手身長の9倍） |
| 地平線（スタンド下端）の画面Y比 | 15 〜 17.5% |
| ボール／プレーの中心の画面Y比 | 約 55 〜 60% |
| 選手の見かけ身長 | 手前で画面幅の約 11%、奥で約 7% |
| 手前／奥の選手サイズ比（プレー領域内） | 約 1.7 〜 1.9 倍 |
| ゴール幅（約60m先） | 画面幅の 14 〜 16% |
| ゴール幅（約15m先、ゴール裏視点） | 画面幅の約 68% |
| タッチラインの外側 | 芝が続き、遠方の隅だけ陸上トラック色 |

**重要**: 原作は「実寸 68m x 105m のピッチに、身長約2mの選手」という**幾何的に正直なスケール**だった。
つまりピッチ幅は選手身長の約34倍。

## 2. 自作の測定値と差分

| 項目 | 原作 | 自作(調整前) | 判定 |
|---|---|---|---|
| 地平線の画面Y比 | 15〜17.5% | 18.1% | ✅ 一致 |
| 見えるピッチの奥行き | 約47m | 925px ≒ 19人身 | ✅ 同等 |
| ボール位置の可視ピッチ幅 | 9人身 | 8人身 | ✅ 同等 |
| 手前／奥の選手サイズ比 | 1.7〜1.9倍 | 約1.7倍 | ✅ 一致 |
| 選手の見かけ身長 | 画面幅の11% | 画面幅の8.7% | ✅ 近い |
| ボールの画面Y比 | 55〜60% | 76% | ⚠️ 下寄り |
| ゴール幅(約60m先) | 14〜16% | 4.5% | ❌ 乖離 |
| **ピッチ幅（選手身長単位）** | **約34人身** | **約9.6人身** | ❌ **根本差** |
| **ピッチ縦横比** | **1:1.54** | **1:3.75** | ❌ **根本差** |
| タッチラインの外側 | 芝が続く | 暗い虚無 | ❌ 廊下に見える |

### 結論: カメラの画角は既にほぼ原作どおりだった

「見える範囲」「選手の大きさ」「遠近の強さ」はいずれも原作と同等で、**カメラ（投影）はほぼ正しい**。
にもかかわらず画が似ていない原因は1点に集約される:

> **ピッチが、選手に対して約3.6倍細い。**
> 原作はピッチ幅＝選手身長の34倍、当実装は9.6倍しかない。

その結果、原作ではタッチラインが常に画面外にあってピッチが「広がり」を持つのに対し、
当実装ではタッチラインが常に画面内に収まり、奥へ行くほど細い帯に収束して「廊下」に見えていた。

なお `PITCH_HEIGHT = VIEWPORT_HEIGHT * 2.5` は Phase 0 で
「CLAUDE.md の『縦長ピッチ 縦:横 ≈ 1.5:1』がビューポートを指すのかピッチ全体を指すのか
明記が無いため、ビューポート側と解釈した」という**仮定**で決められた値（`src/config/pitch.ts` のコメント）。
CLAUDE.md の文言は「ピッチ」であり、実寸比 1:1.54 とも一致するため、**この仮定自体が誤りだった可能性が高い**。

## 7. ビューポートの横長化 (2026-08-18、実プレイ報告への対応)

### 発覚経緯

ユーザーが実際にブラウザでプレイし、「画面が縦長で原作と全く違う」と報告。段階1でカメラ俯角
(16.7°)・ピッチ幅(選手32.7人分)を原作に合わせたはずだったが、実プレイの見た目は原作(横長の
テレビ画面)と根本的に異なっていた。

### 根本原因

Phase 0 の実装が CLAUDE.md「縦長ピッチ（比率 縦:横 ≈ 1.5:1）の縦スクロールカメラ」を
**「ビューポート(画面)自体を縦長にする」**と解釈し、`VIEWPORT_WIDTH=480 / VIEWPORT_HEIGHT=720`
(2:3 縦長) にしていた。しかしこの一文は**ピッチ(実世界のフィールド、105m×68m=1:1.54)**を
指しており、それを映す**画面自体は原作でも横長**(SNESネイティブ256x224+横伸び1.65倍、
scratchpad参照動画のクロップ実測 1668x883=1.89:1、いずれも横長)。この誤読は既に
`docs/screen-geometry.md` 6節 (2026-08-16) で「この仮定自体が誤りだった可能性が高い」と
指摘されていたが、「段階4で手触りとして評価してから判断する」として先送りにしていた —
今回のユーザーの実プレイ報告が、まさにその評価だった。

### 修正内容

1. **`VIEWPORT_WIDTH` 480 → 1280** (`VIEWPORT_HEIGHT` は720のまま。16:9=1.78、原作実測1.89に近い)
2. **`PITCH_WIDTH` を独立定数へ切り離し**: 旧実装は `PITCH_WIDTH = VIEWPORT_WIDTH` (画面幅と
   1:1) だったが、横方向にもカメラが追従する現行実装ではこの等式に意味が無く、画面幅を
   変えるたびに sim/ 側の全距離しきい値の基準 (ピッチの論理寸法) が連動して動く副作用がある。
   `PITCH_WIDTH = 480` (旧VIEWPORT_WIDTHと同値)・`PITCH_HEIGHT = 1800` (旧値そのまま) を
   即値で固定し、sim/ 側を完全に無変更に保った。
3. **`NEAR_WIDTH_RATIO` 4.0 → 1.5** (`render/viewConstants.ts`): 画面横方向のズーム量を
   決めるこの定数を、viewportWidth の拡大率 (480→1280 = 2.667倍) に反比例させて再導出した。
   `camHeight = (viewportHeight-horizonY)*PITCH_WIDTH/(R*viewportWidth)` の式で
   `R*viewportWidth` を一定に保つことで、**俯角(=camHeightで決まる)を完全に不変に保ちつつ**、
   横長画面いっぱいに「より広く」ピッチを見せる(伸縮させない、near depthで見えるワールド幅を
   画面幅の拡大に比例して増やす)効果になる。

### 検証結果 (`npm run view:metrics`)

| 項目 | 修正前 (縦長480x720) | 修正後 (横長1280x720) | 原作実測 |
|---|---|---|---|
| カメラ俯角 | 16.7° | **16.7°(不変)** | 15〜22° |
| ピッチ幅=選手何人分 | 32.7人 | **32.7人(不変)** | 約34.5人 |
| 地平線の画面Y比 | 18.1% | **18.1%(不変)** | 15〜17.5% |
| ボールの画面Y比 | 68.0% | **68.0%(不変)** | 55〜60% |
| 画面の縦横比 | 480:720=0.67 (縦長) | **1280:720=1.78 (横長)** | 1.78〜1.89 (横長) |

俯角・ピッチ幅(人数換算)・地平線Y比・ボールY比は導出上の理由により完全不変 (垂直方向の幾何は
viewportWidthに依存しない式になっている、上記③参照)。画面の縦横比だけが縦長→横長へ転換し、
原作の画面形状に一致した。

検証: 全573テストgreen (sim/ 無変更のため回帰ゼロ)、determinism OK、build OK。ブラウザで
実際に横長画面(1280x720)でのプレイを確認、`.shots/v5-landscape-mid.png` に証跡を保存。

### 既知の残課題 (今回は対象外、記録のみ)

- **ボール位置で見える横幅(選手何人分)**: 修正前13.4人・修正後35.7人 (いずれも原作実測9人分から
  乖離、悪化方向)。これは「近接depthでの視野角(NEAR_WIDTH_RATIO)」というズームレベルの指標で、
  今回対象にした「俯角・地平線Y比・画面縦横比」(=V-0でユーザーが確定した3値)とは別の軸。
  今回は「画面比率が原作と全く違う」という最優先の訴えに応じて画面形状(縦横比)の修正に絞り、
  この既存の乖離(段階1から未解決)には手を付けていない。次にカメラのズーム感を調整する時の
  課題として残す。
- **PITCH_HEIGHT:PITCH_WIDTH比 (1:3.75、実寸1:1.54から2.3倍長い)**: 6節で記録済みの
  未解決の乖離。今回のビューポート修正で画面の縦横比は原作に合ったが、ピッチそのものの
  縦長さ(サイド攻撃の窮屈さ・縦への走破時間という戦術上の課題)は変わっていない。
  screen-geometry.md 6節の「段階4で手触りとして評価」の対象として残る。
- **ブラウザpaneのリサイズ挙動**: 調査中、`resize_window` で任意サイズへ変更した直後は
  一時的にキャンバスが正しく描画されない (プレビューpaneのアーティファクト、`preset`
  指定のリサイズやフルリロード後は正常) ことを確認した。実際のゲーム/描画ロジックの
  バグではない (canvas直接ピクセル読み取りで内容自体は正しいことを確認済み) が、
  今後の目視検証では「リサイズ後は必ずフルリロードしてから撮る」を徹底すること。
