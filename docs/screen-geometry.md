## 1. 原作の測定方法と結果

Web収集した原作プレイ画面 22枚（96 / 95 / 94WCE / 94WCFD / 初代）のうち、SNESネイティブ解像度
(256x224) の6枚を主資料にした。**画像そのものは一切流用していない**（CLAUDE.md「完全オリジナル素材」）。
測定は「既知の実寸（ゴール幅7.32m、ペナルティエリア深さ16.5m、ペナルティアーク弦14.6m、ピッチ幅68m）を
物差しにして、透視投影 `y = y_h + C/z`, `x = W/2 + focal·Δx/z` を当てはめる」方式。

| 項目 | 原作の測定値 |
|---|---|
| 焦点距離 focal | 画面幅の約 1.42 倍 |
| 一度に見えるピッチの奥行き | カメラから約 15m 〜 64m（**約47m**） |
| ボール位置での可視ピッチ幅 | 約 17.7m（≒ 選手身長の9倍） |
| 地平線（スタンド下端）の画面Y比 | 15 〜 17.5% |
| ボール／プレーの中心の画面Y比 | 約 55 〜 60% |
| 選手の見かけ身長 | 手前で画面幅の約 11%、奥で約 7% |
| 手前／奥の選手サイズ比（プレー領域内） | 約 1.7 〜 1.9 倍 |
| ゴール幅（約60m先） | 画面幅の 14 〜 16% |
| ゴール幅（約15m先、ゴール裏視点） | 画面幅の約 68% |
| タッチラインの外側 | 芝が続き、遠方の隅だけ陸上トラック色 |

**重要**: 原作は「実寸 68m x 105m のピッチに、身長約2mの選手」という**幾何的に正直なスケール**だった。
つまりピッチ幅は選手身長の約34倍。

## 2. 自作の測定値と差分

| 項目 | 原作 | 自作(調整前) | 判定 |
|---|---|---|---|
| 地平線の画面Y比 | 15〜17.5% | 18.1% | ✅ 一致 |
| 見えるピッチの奥行き | 約47m | 925px ≒ 19人身 | ✅ 同等 |
| ボール位置の可視ピッチ幅 | 9人身 | 8人身 | ✅ 同等 |
| 手前／奥の選手サイズ比 | 1.7〜1.9倍 | 約1.7倍 | ✅ 一致 |
| 選手の見かけ身長 | 画面幅の11% | 画面幅の8.7% | ✅ 近い |
| ボールの画面Y比 | 55〜60% | 76% | ⚠️ 下寄り |
| ゴール幅(約60m先) | 14〜16% | 4.5% | ❌ 乖離 |
| **ピッチ幅（選手身長単位）** | **約34人身** | **約9.6人身** | ❌ **根本差** |
| **ピッチ縦横比** | **1:1.54** | **1:3.75** | ❌ **根本差** |
| タッチラインの外側 | 芝が続く | 暗い虚無 | ❌ 廊下に見える |

### 結論: カメラの画角は既にほぼ原作どおりだった

「見える範囲」「選手の大きさ」「遠近の強さ」はいずれも原作と同等で、**カメラ（投影）はほぼ正しい**。
にもかかわらず画が似ていない原因は1点に集約される:

> **ピッチが、選手に対して約3.6倍細い。**
> 原作はピッチ幅＝選手身長の34倍、当実装は9.6倍しかない。

その結果、原作ではタッチラインが常に画面外にあってピッチが「広がり」を持つのに対し、
当実装ではタッチラインが常に画面内に収まり、奥へ行くほど細い帯に収束して「廊下」に見えていた。

なお `PITCH_HEIGHT = VIEWPORT_HEIGHT * 2.5` は Phase 0 で
「CLAUDE.md の『縦長ピッチ 縦:横 ≈ 1.5:1』がビューポートを指すのかピッチ全体を指すのか
明記が無いため、ビューポート側と解釈した」という**仮定**で決められた値（`src/config/pitch.ts` のコメント）。
CLAUDE.md の文言は「ピッチ」であり、実寸比 1:1.54 とも一致するため、**この仮定自体が誤りだった可能性が高い**。

## 3. 段階1で実施した調整（すべて描画層のみ、`src/sim/` は無変更）

| 変更 | 内容 | ファイル |
|---|---|---|
| 調整パラメータの集約 | 画面の見え方を決める値を1ファイルへ。`npm run view:metrics` が同じ値を読む | `src/render/viewConstants.ts`（新規） |
| 芝のランオフ | タッチライン/ゴールラインの外側にも芝を延ばし（±2800px）、「暗い虚無」を解消 | `src/render/pitchPerspective.ts` |
| 最遠部の処理 | 描画上限を 3200→6000 に延ばし、外周色を土色→かすみと同系の暗色へ。芝がスタンドの影へ溶ける | 同上 |
| レーダー縮小 | 画面幅22%→15%（占有面積 12.6%→5.6%）、不透明度82%で裏が透ける | `src/config/pitch.ts` / `PitchScene.ts` |
| カメラの純関数化 | 死んでいた旧・真上視点用 `computeCameraY` を廃し、実際に使う追従計算をテスト可能な純関数へ | `src/render/camera.ts` |
| 計測ツール | 原作と同じ項目を解析的に算出する表を出力 | `tests/render/viewMetrics.test.ts`（新規） |
| カメラ挙動テスト | 追従/先読み/振れ/浮き球/セットプレーの5項目を数値で検証 | `tests/render/cameraBehavior.test.ts`（新規） |

## 6. 【2026-08-16 訂正】D-1（ピッチ寸法の変更）は取り消した

**この節の以下の内容は取り消しました。** 「ピッチが選手に対して3.6倍細い」は選手の
**描画上の**大きさとの比であり、決めているのは sim ではなく描画層の `NEAR_WIDTH_RATIO` でした。
1.18→4.0 にするだけで解決しています（カメラ俯角 45.4°→16.7°、ピッチ幅=選手32.7人分）。
`src/sim/` は無変更、AIの再調整も不要です。詳細は `docs/visual-overhaul-proposal.md` 1-6節。

ゲームプレイ上の比率（縦に2.3倍長い）は残っており、段階4で手触りとして評価します。

以下は取り消した旧内容（記録として残す）:

### ~~段階4の冒頭で必ず行う確定タスク（D-1）~~

**採用案: 幅を広げる**（`PITCH_WIDTH` 480 → 約1200、1200x1800 = 1:1.5）。
長さ・選手速度・ゴール幅の体感を維持したまま、横の広がりだけ原作に近づける。
（長さを縮める案は Y方向の全しきい値に波及し、ライン押し上げ/サポートラン/オフサイドが
総崩れになるため不採用。）

「いつかやるかも」ではなく**確定タスク**。AI調整を終えてから寸法を変えると二度手間になるため、
**段階4の最初のタスクとして実施する**（ユーザー確定、2026-08-16）。

### 実施時に洗い出すべき影響範囲

- **自動追従するもの**: フォーメーション配置（`formations.ts` は `xFrac` 基準）、
  ピッチのライン類（`pitchGeometry.ts` は `PITCH_WIDTH` 基準で相対計算）、
  レーダー寸法（`RADAR_HEIGHT` は縦横比から導出）、投影（`cameraWorldX = PITCH_WIDTH/2`）
- **要再調整（X方向を含む距離しきい値）**:
  - `teamAIConstants.ts`: マークゾーン深度450px、マーク対象のボール除外120px、
    マークのスタンドオフ48px、追跡権の距離バケット64px、団子判定150px、
    ホームdeadzone 28px、リーシュ半径180/280px、サポートランのX離隔64px
  - `ballConstants.ts`: カーソルパス射程220px、キック射程30px、ドリブル半径20px
  - `boundsConstants.ts`: セットプレー除外半径130px、ゴールキック除外深度250px
  - `goalkeeperConstants.ts`: **ゴール幅80px はピッチ幅の16.7%→6.7%になるため要拡大**
    （実寸比 10.8% なら約130px。原作は10.8%だが当実装は得点しやすさのため広めでよい）
  - `tacklePhase`/`foul.ts` の接触半径、`cpuDefenseAI.ts` の密着判定
- **再較正が必要な検証基準**: `soccerSanity.test.ts` の団子度・プレス距離・マーク距離、
  `behaviorSpec.test.ts` の xShift・nearSupport（いずれも px 絶対値のため）
- **やり方の方針**: 「距離しきい値をピッチ幅に対する比率で定義し直す」形にリファクタしてから
  幅を変えると、以後の寸法変更が安全になる（段階4で検討する）
