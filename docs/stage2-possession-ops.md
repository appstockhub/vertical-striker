## 2. 発見した機械的欠陥と修正

### 欠陥1 【修正済み】START ライン操作が発動しない

- **症状**: STARTを30tick押し続けても `manualLineOffset` が 0 のまま。押しても何も起きず、
  画面表示も無いので「効かないボタン」にしか見えない。
- **原因**: 保持文脈の判定に `linePossessionTeam`（**90tickのヒステリシス付き**）だけを使っていた。
  試合開始直後・競り合い中・保持が入れ替わった直後の1.5秒間は `null` のままで、
  `if (Start && (attacking || defending))` がどちらも false になり分岐に入らなかった。
- **修正**: ヒステリシスが要るのは「AIが一斉に行進しない」ためであって、人間の入力を
  受け付けるかどうかには要らない。`linePossessionTeam` → 現在の接触 → 直近の接触 の順に
  フォールバックして、押した時に必ず反応するようにした（`src/sim/update.ts`）。

### 欠陥2 【修正済み】A/X/Y/ワンツー/リフティングに画面フィードバックが一切無い

- **症状**: キックフラッシュが「Bチャージの解放」でしか出ず、A/X/Y・ワンツー・リフティング・
  蹴り出しドリブルは**押しても画面上まったく無反応**。押せたのか分からない。
- **修正**: ボール速度の跳ね上がり（>2.0px/tick）で検出する方式に変え、経路を問わず
  1箇所で拾えるようにした（`src/render/PitchScene.ts`、描画専用）。

### 欠陥3 【修正済み・ドリルモードの実装バグ】ドリルモードで A/X/Y が一切発動しない

- **症状**: 操作確認モードで A/X/Y を押してもボールが 0.00 のまま動かない。
- **原因**: ドリルモードは味方21人をゴールライン際へ退避させるため、**味方全員が最終ラインより前**に
  なり、パスが毎回オフサイド判定 → `offsideRestartBall` でボールが速度0のまま別位置へ移される。
  「ボタンが壊れている」ようにしか見えない状態だった。**実機で押して初めて発覚**
  （プローブはオフサイドOFFで組んでいたため素通りしていた）。
- **修正**: ドリルモードではオフサイド判定を行わない（`offsideActive`、`src/sim/update.ts`）。

### 欠陥4 【修正済み・ドリルモードの実装バグ】カーソルが退避させた選手へ移る

- **症状**: ドリルモードに入ると、操作対象がピッチ端に退避させた別人に切り替わることがある。
- **原因**: 退避先をタッチライン外に置いても `clampToPitchBounds` でピッチ内へ押し戻され、
  そこへカーソル自動追従が働いていた。
- **修正**: ドリルモード中はカーソルを固定。退避は「両ゴールライン際に密集」へ変更。

### 【未修正・要判断】溜めと蹴りの強さの関係が仕様と逆

- **実測**: 総合パワー（水平と垂直初速の合成）が 短押し8.79 → 長押し8.46 と**下がる**。
  CLAUDE.md 続編仕様「基本的に押す長さがそのままボールの強さになる」とは逆方向。
- **なぜ直さなかったか**: `HIGH_ARC_SPEED_MULTIPLIER` を 0.7→0.85 にすると仕様どおり（総合9.52）に
  なるが、**それだけで観戦シミュレーターの正常性基準が3件落ちる**ことを実測で確認した
  （プレス距離155px>150 / サポートラン0.897<0.9 / 振動1人。いずれも閾値際の揺らぎ＝
  このプロジェクトで繰り返し起きている「物理変更が試合全体のバタフライ効果で既存AIの
  潜在ケースに当たる」パターン）。
  これは**AIバランスの再調整と不可分**であり、段階2（操作感）で私が独断で入れると
  ユーザーの手触り評価にバランス変化が混入する。段階4で寸法変更とあわせて扱う。
  プローブでは `[要判断]` として report-only で記録している。

### 【未実装・要設計判断】パスカーソルの L/R 切り替え

CLAUDE.md「L/R/START でその矢印カーソル（パス先候補）を切り替えられる」は未実装。
ただし L/R は既に**シフトキック**（キック時に押していると45度シフト）と
**蹴り出しドリブル**（L+R同時押し）に使われており、「タップで切替 / ホールドで別機能」の
切り分けを設計しないと暴発する。今回は欠陥ではなく未実装機能として報告に留めた。

## 3. 操作確認モード（ドリルモード）の使い方

| キー | 動作 |
|---|---|
| **T** | 操作確認モードの ON / OFF |
| **R**（モード中） | ボールを足元へ戻す |
| **P** | 練習モード（CPUがボールに関与しない。ドリルモードとは別） |

### 入り方

1. `npm run dev` → http://localhost:5173 （または GitHub Pages 公開版）
2. 試合前設定で難易度を選び **Enter** で試合開始
3. 試合中に **T** を押す

押した瞬間に、
- 操作対象がハーフウェーライン付近の中央（背番号10の選手）に固定され、
- ボールがその足元に置かれ、
- 他の21人は両ゴールライン際へ退避して完全に静止し、
- CPUの攻撃/守備判断も一切走らなくなる。

もう一度 **T** で通常の試合へ戻る（選手の配置はそのまま。試合を続けるならフルタイム後の **R** でリマッチ推奨）。

### 画面に出る情報（左上のパネル）

```
── 操作確認モード  T:解除  R:ボールを足元へ ──
方向 ↑   押下 [X(V)]                    ← 現在の入力状態
溜め 0/30   ボール 速度7.07 高さ4.0       ← 溜めフレーム / ボールの実測値
蹴出しドリブル off   ライン操作 0          ← 状態フラグ
直近: X ロングフィード  初速7.07 弾道zVel3.98 溜め0  (0f前)   ← 何が発動したか
カーブ: (未発動)                          ← カーブの方向と経過
```

「直近:」の行に**発動した操作の名前**が出るので、「今の操作が発動したのか / しなかったのか」を
判別できる。押しても行が変わらなければ、その操作は発動していない。

## 4. ユーザーが触って評価すべきポイント（チェックリスト）

機械的な「発動するか」は上記で全て確認済み。以下は**数値では判断できない手触り**なので、
実際に触っての評価をお願いしたい。ドリルモード（T）で1つずつ試すのが早い。

### A. ドリブル
- [ ] 8方向の切り返しが素直か。斜めが入れづらい／意図しない方向に行くことはないか
- [ ] ボールが足元に吸着しすぎないか、逆に離れすぎないか（CLAUDE.md「吸着しすぎない」）
- [ ] **蹴り出しドリブル（L+R同時押し→片方継続）**: 通常ドリブルとの差が体感できるか。
      「リスクを取って加速している」感覚があるか（実測では前進が123→176px、足元との距離3→8px）

### B. キック（保持時の心臓部）
- [ ] **溜めの手応え**: 押している時間が長いほど「強く蹴った」と感じるか。
      ※実測では総合パワーが逆に下がっている（上記の要判断項目）。ここが不満なら段階4で直す
- [ ] 短押しと長押しの**弾道の差**が見て分かるか（到達 0px vs 48px）
- [ ] 方向なしBの弱キック（6.05）が「弱すぎる／ちょうどよい」か
- [ ] **A（進行方向パス）**: 原作で「戦略のキモ」とされた操作。素直に出るか、狙った所へ行くか
- [ ] **X（ロングフィード）**: 浮き球の高さ（到達24.6px）が「ロングフィードらしい」か
- [ ] **Y（カーソルパス）**: 受け手の選ばれ方に納得できるか（意図しない相手へ出ないか）

### C. 続編仕様（12周目実装、いずれも今回が初の動作確認）
- [ ] **シフトキック（L or R + キック）**: 45度ずれるのが直感的か。押し間違えて暴発しないか
- [ ] **カーブ（キック直後6tick以内に別方向）**: 受付6tick（0.1秒）が**実際に狙って入力できる長さか**。
      短すぎるなら伸ばす。曲がり幅28pxが弱すぎ／ちょうどよいか
- [ ] **リフティング（直前の向きと正反対＋B）**: 発生条件が狙って出せるか。
      ドリブル中の切り返しで**意図せず暴発しないか**（ここは特に見てほしい）
- [ ] **START（ライン操作）**: 保持中に押してオフェンスラインが下がるのが分かるか。
      ドリルHUDの「ライン操作」の数値と、実際の味方の動きが一致するか（※ドリルモードでは
      味方が静止しているので、これは通常の試合モードで確認してほしい）

### D. フィードバック全般
- [ ] キックフラッシュが**全ての種類のキック**で出るようになったが、目立ちすぎ／足りないか
- [ ] 溜めメーターが見やすいか
- [ ] 「押したのに反応しない」と感じる操作が残っていないか（あればドリルHUDの「直近:」行が
      変わるかどうかで、入力が届いていないのか発動条件を満たしていないのかを切り分けてほしい）
