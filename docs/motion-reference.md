# 原作モーションリファレンス（動画実測 vs 自作ゲーム）

作成: 2026-08-17（23周目）。
原作のプレイ動画（SNESネイティブ 30fps 録画、183秒、JPN vs THA）からボールを追跡し、
挙動を数値化して自作ゲームと対比する。**7件の不具合修正の「正解値」はここから取る。**

- 分析パイプライン: `scripts/video/analyzeOriginal.py`（構図・縮尺の自動検出）+
  `scripts/video/trackBall.py`（テンプレートマッチング追跡）+ `scripts/video/metrics.py`（指標算出）
- 動画・フレーム・テンプレートはすべて `.gitignore` 済み。**リポジトリ・配布物には数値だけが残る**
- 追跡の検証: マーカー画像12枚の目視確認で12/12がボールに正着（3回の作り直しの末。
  失敗の記録は trackBall.py 冒頭に残した）

## 単位の定義（最重要・誤読防止）

解像度も座標系も違うため、**すべて「選手の身長 = 1」に正規化した無次元値**で比較する。

| | 原作（動画） | 自作 |
|---|---|---|
| 身長の実体 | ボール近傍の選手スプライトの実測高さ。**全身が取れている18〜30ドットのサンプルのみ使用**（部分検出・クラスタ結合は正規化を最大2倍歪めるため除外。分布実測に基づく） | ピッチ幅480px ÷ 32.7人分 = **14.68 world px**（19〜20周目の確定測定値） |
| 時間 | 動画30fps → 60fps tick へ換算 | 60fps tick |

### 系統誤差（読む前に必ず理解すること）

1. **カメラ移動は位相相関で補正済み**（原作はボール追従スクロールのため、画面上の速度は実速度ではない）
2. **疑似3Dの遠近**: 画面の縦方向は地面の距離が圧縮されて写る。横成分が支配的なキックを
   別枠 (`lateral`) で出しており、**速度の絶対値はそちらが最良推定**
3. 原作のスプライトは奥行きでサイズが変わらない可能性が高く、「局所の身長で割る」正規化には
   深さ依存の誤差が残る。**速度の絶対値は±40%程度の系統誤差を見込むこと**。
   一方、**比率・周期・減衰率はこの誤差の影響を受けない**（無次元 or 時間のみ）
4. 30fps録画のため、時間分解能は2 tick。モーション時間（項目4）は範囲でしか言えない

## ⚠️ 想定外の差（相談事項）: 全体テンポが3〜4倍速い

個別の操作より大きい差が1つ出た。**走速もキック速度も、身長比で自作が原作の3〜4倍**。
一方でキック/走速の**比はほぼ一致**（3.3 vs 2.9）しているので、壊れているのは内部バランス
ではなく**絶対テンポ**だけである。

具体的に言うと: 原作の選手が画面幅(約47m相当)を横切るのに約10秒かかるのに対し、
自作は1〜2秒で横切る。「せわしない」「団子になる」「考える間がない」という体感の
根っこはおそらくここにある。

**ただし即座に直すべきとは言えない**：
- 速度の絶対値には±40%の系統誤差がある（それでも3〜4倍は誤差では説明できない）
- 原作の評判は「とにかく速い」（18周目調査）。テンポを落としすぎると原作の身上を失う
- `PLAYER_SPEED_FIXED` を触ると**全AIしきい値・全プレイアビリティテストに波及**する
  （事実上の段階4作業。18周目のファウル距離、17周目のプレス距離などすべて速度前提）

**提案**: 7件の修正が終わってから、`PLAYER_SPEED_FIXED` を 3.0 → 2.0 前後へ落とした
実験ビルドを1本作り、触り比べて判断する（サイドバイサイドの実プレイ比較。
採用するなら段階4のAI再調整とセットで入れる）。
